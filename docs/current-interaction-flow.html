用户主入口

官方人物馆先吸引，再进入 Persona 聊天

首页不是工具台，而是精选人物馆；点进人物卡后直接进入聊天状态。

创作主闭环

创建对象，补资料，蒸馏后进入预览

当前用户端先聚焦创建、预览和聊天，审核工作台后续交给独立 admin 项目。

传播主单位

对外传播的不是 Persona，而是版本级分享身份

分享链接固定绑定到 `persona_version`，旧分享不能被后续编辑漂移掉。

当前运行时交互图

这张图描述 H5、API、Worker 和 DeepSeek 之间的真实协作方式。它对应的是当前 bootstrap 代码态，而不是未来理想架构。 

sequenceDiagram
  participant U as 用户
  participant H5 as H5 Shell
  participant API as apps/api
  participant Store as persona-store/chat-store/auth-store
  participant Worker as apps/worker
  participant DS as DeepSeek

  U->>H5: 打开首页 / persona / share / create / mine
  H5->>API: 调用 /v1/... 业务接口
  API->>Store: 读取 session / persona / version / source / chat

  alt 官方 Persona 聊天
    H5->>API: POST /v1/chats
    H5->>API: POST /v1/chats/:chatId/messages
    API->>Store: 解析 chat target
    API->>DS: chat workflow
    DS-->>API: 结构化回答
    API->>Store: 保存 user + assistant message
    API-->>H5: answer + basisSummary
  end

  alt 用户创建对象
    H5->>API: POST /v1/personae
    H5->>API: POST /v1/personae/:id/sources/text 或 /sources/url
    API->>Store: 写入 pending source
    API->>Worker: URL source ingest
    Worker-->>API: 规范化快照

04

当前 4 条用户端链路

这里把现在仍属于当前用户端范围的交互拆成 4 条路径，审核与发布工作台不再算进主产品链路。

01 官方体验链路

首页精选 -> Persona 聊天

首页精选 -> 点击人物卡 -> Persona 页 -> 首屏看到 persona 先说一句 -> 用户输入 -> 创建 chat session -> 发消息 -> 返回回答 -> 可展开“这句话怎么来的”
  • 首页入口是人物馆，不是工具台。
  • Persona 页首屏直接进入聊天状态。
  • 回答解释层默认折叠，用户主动展开。

02 分享承接链路

外部分享 -> 分享页 -> 继续聊天

外部分享链接 -> /share/:shareSlug -> 直接进入聊天页壳 -> 创建 share_link 类型 chat session -> 继续对话
  • 分享承接的是 `persona_version`。
  • 分享页复用 Persona 页的聊天语言。
  • 分享落地页首屏就能开聊。

03 创建链路

创建 Persona -> 加资料 -> 蒸馏

/create -> ensureAnonymousSession -> 创建 persona -> 添加文本/URL 资料 -> 刷新资料列表 -> 点击“蒸馏并进入预览页”
  • 当前创建页支持匿名 session 起步。
  • 文本和 URL 资料是平级入口。
  • 手机号升级路径已接简化版 H5 登录。

04 蒸馏与预览链路

distill -> candidate version -> preview chat

添加资料 -> POST /distill -> worker distill -> 生成 candidate persona_version -> /preview/:personaVersionId -> 试聊 -> 返回“我的”或等待后续发布链路
  • 预览聊天命中 `draft_version_preview`。
  • 预览访问当前以创建者为中心。
  • “是否公开分享”后续由独立 admin 项目承接。

05

当前关键状态机

这里不是完整数据库状态定义，而是当前最值得需求侧牢牢记住的业务状态面。

角色

Actor Roles

ANONYMOUS USER REVIEWER
  • `ANONYMOUS` 可以开始体验和创建。
  • `USER` 是正式手机号或微信身份。
  • `REVIEWER` 只保留给后续 admin 项目。

Persona 状态

Persona Container

DRAFT -> PROCESSING -> READY -> PUBLISHED \-> REJECTED
  • `persona` 更像容器或归属单位。
  • 当前真正参与聊天、审核、分享的是 `persona_version`。

Version 状态

Persona Version

DRAFT -> CANDIDATE -> PENDING_PUBLISH_REVIEW -> PUBLISHED \-> REJECTED \-> SUPERSEDED
  • 发布和分享都绑定版本，而不是绑定可变 persona。
  • 审核相关状态属于后续 admin 项目衔接范围。

Chat Target

聊天目标三种模式

published_persona draft_version_preview share_link
  • 官方聊的是 `published_persona`。
  • 预览聊的是 `draft_version_preview`。
  • 分享进来聊的是 `share_link`。

06

当前实现与目标产品之间的差距

需求讨论最容易混淆的地方在这里：产品目标已经比较完整，但当前代码态仍然是 bootstrap。后续实现窗口必须明确自己在补哪一层。

已经基本成型

  • 官方人物馆 -> Persona 聊天
  • 分享落地 -> 继续聊天
  • 创建 -> 资料 -> 蒸馏 -> 预览
  • 分享身份绑定 `persona_version`
  • 回答解释层 `basisSummary`

还明显是 bootstrap

  • 真实前端仍是 H5 Fastify shell，不是最终 Taro 双端运行态。
  • 微信小程序还没有真实页面流，只是 scaffold 占位。
  • “我的”入口当前不是完整个人中心，底部导航还需要正式收敛成 `聊天 / 创建 / 我的`。
  • `/v1/feedback` 已存在，但主交互里还没挂完整纠偏反馈。
  • bootstrap 里仍有 `/review` 残留，但它不属于当前用户端产品态。

07

可直接给实现窗口的总述

如果你要把这份文档转给其他窗口，下面这段话可以直接复用。

当前 Hall of Fame 的用户端真实交互闭环已经确定为：官方人物馆吸引进入，Persona 页与分享页都直接承接聊天；用户可在创建页用公开资料创建 persona，并进入 distill 与预览链路；底部导航收敛为 聊天 / 创建 / 我的 。审核与发布工作台不再属于当前用户端范围，后续由独立 admin 项目承接；而以 persona_version 为中心的分享与聊天链路继续承接。
