# 名人堂小程序 V1 设计文档

- 日期：2026-04-10
- 状态：需求已收敛，待进入布局设计
- 范围：V1 公开人格蒸馏平台

## 1. 产品定义

本产品不是严肃问答工具，也不是私密分身或数字复活产品。

V1 的定义是：

> 一个围绕“人格蒸馏”的公开小程序。平台先提供一批官方预置人物，用户可以基于公开资料创建自己的蒸馏对象，与对象对话，并把对象分享给别人继续使用。

产品的核心资产不是单次聊天记录，而是“可被对话、可被分享、可被复用的人格对象”。

## 2. 核心判断

本产品的用户驱动力主要来自以下四类动机：

- 好玩，想和有辨识度的人物对话
- 表达，想把自己喜欢的人物或主题做成一个对象
- 代入，想感受“这个人会怎么想、怎么说”
- 分享，想把做好的对象发给别人继续体验

因此，V1 的成败关键不在于绝对知识准确率，而在于以下四点：

- 蒸馏对象是否“像这个人”
- 创建门槛是否足够低
- 分享出去之后是否足够有趣
- 被分享的对象是否能继续传播

## 3. V1 定位与范围

### 3.1 定位

V1 是一个公开人格蒸馏平台，优先验证以下闭环：

1. 用户被官方名人馆吸引进入产品
2. 用户和官方对象对话，理解产品形态
3. 用户发现自己也能创建对象
4. 用户基于公开资料创建对象
5. 用户将对象分享给别人
6. 别人打开对象后继续对话和传播

### 3.2 V1 明确要做

- 官方人物馆
- 用户基于公开资料创建蒸馏对象
- 对象详情页
- 对话页
- 对象分享
- 对象公开/私用发布选择

### 3.3 V1 明确不做

- 私密聊天记录导入
- 熟人、恋人、逝者纪念场景
- 活着的名人蒸馏
- 投资、医疗、法律等高风险决策建议
- 声音复刻、视频复刻、数字形象复刻
- 开放式 UGC 广场
- 用户端 reviewer 审核页 / 审核工作台

说明：

`私密分身产品` 是后续可能的独立方向，但不应与 V1 的公开人格平台混做。前者需要单独的权限、隐私、删除、投诉和审核体系。

补充约束：

- 审核能力后续仍会存在，但操作面放到独立 `admin` 项目，不放在当前 H5 / 小程序用户端中

## 4. 目标用户

V1 先聚焦两类用户：

- 普通体验用户：被官方名人馆吸引，愿意试玩、提问、分享
- 轻创作者用户：愿意基于公开资料创建一个可聊天对象，并分享给别人

V1 不以专业研究者、严肃决策者或高风险咨询场景为目标用户。

## 5. 产品结构

### 5.1 首页结构

首页主轴已经确定为：`官方人物馆优先`

建议的首页区块如下：

1. 顶部定位文案
   `和被蒸馏的人格对话。也创建一个属于你的对象。`
2. 官方人物馆
   首屏展示 6-8 个精选对象
3. 示例问题
   每个对象卡片直接展示可点问题，帮助用户快速进入对话
4. 创建入口
   作为第二动作出现，不抢首页主轴
5. 精选分享对象
   第一版可人工精选，不做开放式广场

设计原则：

- 首页看起来像“策展馆”，不是工具台
- 先让用户玩，再让用户理解“我也能做”
- 精选少量高辨识度对象，不追求数量

### 5.2 对象创建流程

V1 创建流程控制在 4 步内：

1. 命名对象
   可选类型：
   - 历史人物
   - 作者 / 博主
   - 原创人格
2. 提供资料
   仅支持：
   - 粘贴文本
   - 公开网页链接
3. 定义蒸馏重点
   由用户选择偏好，而不是手写长 prompt：
   - 更偏观点
   - 更偏说话风格
   - 更偏经历背景
   - 更偏回答方式
4. 预览并发布
   预览页展示：
   - 这个对象像谁
   - 基于哪些资料
   - 适合问什么
   - 3 个示例回答

发布方式：

- 仅自己使用
- 公开分享

### 5.3 对话页设计原则

对话页不能只是一个通用聊天界面，需要体现“人格蒸馏”本身。

固定元素如下：

1. 对象头部
   - 对象名
   - 官方 / 用户创建标识
   - 基于多少份资料蒸馏
   - 一句话人格说明
2. 建议提问
   首轮展示 3-4 个可点问题
3. 回答双层结构
   - 蒸馏回答：像这个人会怎么说
   - 依据：这段回答主要参考了哪些资料或观点
4. 纠偏入口
   - 不够像这个人
   - 这段没有依据
5. 分享入口
   分享的是对象本身，不是聊天截图

## 6. 官方人物馆首批名单

首批路线已确定为：`混搭精选`

入选原则：

- 已故人物优先
- 资料丰富
- 人格差异大
- 一眼能理解“可以怎么聊”

首批 6 个对象如下：

### 6.1 秦始皇

- 一句话人设：统一六国的极致决断者，关心秩序、权力与长远控制
- 示例问题：
  - 如果你面对一个分裂失序的局面，会先统一思想还是先统一制度？
  - 为了长期稳定，强硬手段是否值得？
  - 你怎么看“天下一统”背后的代价？

### 6.2 诸葛亮

- 一句话人设：以审势、谋划、用人为核心的长期主义军政参谋
- 示例问题：
  - 资源不足时，应该先补短板还是赌一次大机会？
  - 你怎么判断一个人能不能重用？
  - 局势不利的时候，该坚持还是撤退？

### 6.3 苏轼

- 一句话人设：在失意与豁达之间找到生命张力的文人
- 示例问题：
  - 人处在低谷时，怎么和自己相处？
  - 理想与现实总冲突，怎么办？
  - 你怎么看“活得有趣”这件事？

### 6.4 王阳明

- 一句话人设：强调知行合一、向内求心力的行动型思想家
- 示例问题：
  - 知道很多道理却做不到，问题出在哪？
  - 做决定时该听理性还是听内心？
  - 一个人怎么建立真正稳定的内核？

### 6.5 曹操

- 一句话人设：兼具雄心、现实感和用人手腕的复杂权力人物
- 示例问题：
  - 做大事时，名声和结果哪个更重要？
  - 你怎么对待比自己强的人？
  - 乱世里，仁义到底值多少钱？

### 6.6 查理·芒格

- 一句话人设：反常识、重判断框架、讨厌愚蠢决策的长期主义者
- 示例问题：
  - 判断一个机会值不值得做，第一步看什么？
  - 怎样避免自己做出愚蠢决定？
  - 长期来看，普通人最该建立什么能力？

## 7. 内容与合规边界

V1 从产品层面就需要把边界做清楚，而不是上线后再补。

### 7.1 对象来源边界

- 官方对象优先使用公开、可追溯、资料充分的已故人物
- 用户创建对象仅允许基于公开资料或用户明确拥有权利使用的内容
- 上传入口必须提示：仅提交你有权使用或公开可访问的内容

### 7.2 对话表达边界

- 对话结果必须区分“资料依据”和“风格化推演”
- 不把模型输出包装成真实人物原话
- 不鼓励用户将回答用于高风险现实决策

### 7.3 产品形态边界

- V1 是公开人格平台，不是私密关系模拟器
- V1 不提供熟人复刻、恋人陪伴、逝者纪念等高情绪场景
- V1 不开放活人名人蒸馏，降低投诉、侵权和误导风险

## 8. 体验原则

V1 需要坚持以下体验原则：

- 首屏 10 秒内让用户理解产品
- 用户 1 分钟内能做出第一个对象
- 用户第一次对话就能感受到“这个对象有个性”
- 用户第一次分享时，分享的是“对象”，不是单次回答
- 页面语言更接近策展和人格介绍，而不是 AI 工具说明书

## 9. 布局设计阶段的输入约束

后续做布局和视觉时，需要基于以下已定约束继续推进：

- 首页首屏以官方人物馆为中心
- 创建入口是第二动作，不抢主入口
- 对象页必须先于聊天输入，先建立对象认知
- 对话页要保留“依据”层
- 分享卡必须突出对象身份、人格说明和可继续聊天
- 用户端底部主导航只保留 `聊天 / 创建 / 我的`
- `审核` 不作为当前用户端导航入口，后续放到独立 `admin` 项目
