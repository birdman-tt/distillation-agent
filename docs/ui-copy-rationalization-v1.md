# 用户端文案统一稿 V1

- 日期：2026-04-22
- 目标：统一当前用户端文案风格，解决“过于僵硬、不够简洁”的问题
- 适用范围：当前 H5 bootstrap 用户端，可直接供后续实现窗口替换
- 主要来源：
  - `.worktrees/task1-bootstrap/apps/client/src/h5-app.ts`
  - `.worktrees/task1-bootstrap/apps/api/src/seed/official-personae.ts`

## 1. 本轮范围

本轮处理：

- 用户端固定 UI 文案
- 状态文案、空态文案、错误文案
- 分享页、创建页、预览页、我的页、对话页的固定说明文案
- 官方人物首屏简介、推荐问题、示例回答

本轮不处理：

- slogan：`只差一句开场`
- 任务卡文案
  - 指创建工作台中的任务卡块及其说明
  - 如：`先把资料喂进去`、`先听它怎么开口`、`最后才进入发布`
- 动态生成的聊天回答正文
- 动态 `basisSummary` 内容本身

额外约束：

- `review / reviewer / 审核入口 / 发布审核` 不再作为用户端文案优化对象
- 这类文案在用户端统一按“删除入口”处理，不做润色保留

## 2. 统一原则

- 能短就短，不解释产品架构
- 少用“后台味”表达，如：`入口`、`链路`、`persona`
- 优先使用用户熟悉词：`聊天`、`创建`、`我的`
- 标题尽量控制在 4-8 个字
- 按钮尽量控制在 2-4 个字
- 状态文案只说当前状态，不解释内部流程
- 同一动作在不同页面尽量只保留一种说法

## 12. 最终执行口径

后续实现窗口如果要改文案，按以下顺序执行：

1. 先删除用户端 review 相关文案和入口
2. 再统一底部导航为 `聊天 / 创建 / 我的`
3. 再替换创建、预览、分享、我的、对话页的固定文案
4. 最后再处理官方人物首屏简介、推荐问题、示例回答

不允许出现的用户端词汇：

- `reviewer`
- `审核入口`
- `发布审核`
- `当前 persona`
- `链路`
- `worker`
