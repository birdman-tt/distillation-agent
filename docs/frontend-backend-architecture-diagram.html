Hall of Fame Miniapp Architecture

Separate frontend and backend architecture views for the Hall of Fame miniapp. The diagrams combine the locked target design in docs/technical-architecture.md with the current engineering bootstrap in .worktrees/task1-bootstrap.

Frontend Architecture
One business frontend, two runtime targets

Frontend Boundary

  • One business frontend codebase, not separate H5 and WeApp logic trees.
  • Platform divergence is isolated in adapters.
  • API access stays behind services and api-client.

Bootstrap Reality

  • Current worktree already has client entrypoints, ui-tokens, api-client, and env loading.
  • The full Taro pages/features layout is target-state, not fully scaffolded yet.
  • The package split is already pointing in the right direction.
Backend Architecture
Unified API plane + bounded worker compute plane

Backend Rule

  • API owns lifecycle transitions, authorization, persistence, review gating, and share issuance.
  • Worker owns bounded computation only: source-ingest and distill.
  • Contracts and domain types remain shared packages, not duplicated app-local models.

Current Bootstrap

  • PostgreSQL schema, dynamic persona repository, review flow, chat workflow, and worker split already exist.
  • Auth is still bootstrap-grade and in-memory.
  • Official personae are still seed-backed while user-created personae are DB-backed.

Critical Flows

  • Source URL import: API creates pending source, worker computes snapshot, API persists document/evidence.
  • Distill: API prepares approved sources, worker computes candidate output, API persists candidate version.
  • Publish remains reviewer-gated and share identity remains version-bound.
